## 0. 定位（对外一句话）

**会校准的规划器 + 一键可行方案。** 训练内核不自研（交给 musubi / transformers+peft），SuperTuner 的差异化是「跑前可校验 + 跑后可闭环 + 许可门禁」。v0.2 全部任务服务这条定位，不碰训练内核、不做视频全参、不做多卡。

## 2. 执行顺序与依赖

```
T1 自校准 ──┐
T2 实测预算 ─┼─> 全量回归 ─> 独立评审 ─> lead 汇总(ARCHITECTURE/MEMORY)
T3 统一选择 ─┤
T4 OOM 兜底 ─┘
T5 对外声明对齐：所有 P0 合并进主分支前收口
T6/T7（P1）在 T3 之后按余量插入
```

- **T1 最优先**：增量最小（`memory_report` 已交付 2651.5 vs 2814）、差异化最大，是「会校准的规划器」的护城河。
- **T2 先于 T3**：统一选择需要实测显存作真值输入。
- **T3 先于 T4**：OOM 重试方案由统一选择器生成。
- **T5 收口**：对外口径总闸，防止中间态被误读为「已验证」。
- T6/T7 为 P1，不阻塞主线，T3 之后按余量插入。

## 3. 首个执行任务：T1 跑后自校准（最优先）

**目标**：把每次「计划 vs 实测」沉淀成校准库，让下一次规划带上「已校准 N 次 + 偏差」，形成同类框架都没有的闭环。

**输入**：已交付的 `memory_report.json`（`{planned_mib, measured_peak_mib, delta_mib, delta_pct, device, family, stage, adapter, ...}`）。

**要做**：
1. 新增校准存储：server 侧按 `(family, stage, adapter, quant_base, blocks_to_swap)` 聚合 `memory_report`（JSONL 或 SQLite 表）。
2. planner / plan 结果读取校准库，命中时输出 `calibration: {count, avg_delta_pct}`，并在 plan 标注「已校准 N 次（平均偏差 x%）」；UI（RunDetail/Planner）显示。
3. 偏差修正**只做标注 + 建议**，不静默改预算（避免自校准把误差滚大）；N<3 只标「样本 N 次」，不强行给修正值。

**涉及文件**：`engine/src/supertuner_engine/{plan,events,schema}.py`、`packages/core/src/{events,contracts}.ts`、`packages/web/src/pages/{RunDetail,Planner}.tsx`、`packages/server/src/{routes,supervisor,db}.ts`、`engine/tests/test_plan.py`。

**验收**：
- 连续 2 次同 spec 训练后，第 3 次 plan 出现「已校准 1 次（偏差 x%）」。
- 校准键含 5 元组；不同 quant/swap 不串档。
- 回归：engine pytest、server、web 全绿；typecheck/build 通过。

**不做**：不静默改 `vram_budget_mib`；单次 N=1 不强行修正。
